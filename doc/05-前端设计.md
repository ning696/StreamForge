# StreamForge 前端设计

## 1. 目标

前端负责提供可用的视频会议体验，覆盖注册、登录、创建房间、加入房间、LiveKit 音视频通话、屏幕共享、聊天、成员状态和媒体控制。

技术栈固定为：

- Vue 3
- TypeScript
- Vite
- Pinia
- Vue Router
- Element Plus
- `livekit-client`

## 2. 页面路由

| 路由 | 页面 | 说明 |
|:---|:---|:---|
| `/login` | 登录页 | 输入账号和密码，登录成功后进入首页 |
| `/register` | 注册页 | 输入账号、密码、用户名，注册成功后进入首页或登录页 |
| `/` | 首页 | 展示当前用户、创建房间、输入房间号加入 |
| `/rooms/:roomId` | 房间页 | 视频会议主界面 |
| `/:pathMatch(.*)*` | 404 页 | 未匹配路由 |

未登录用户访问首页和房间页时，跳转到 `/login`。MVP 这里的“未登录”只指前端本地没有用户信息，不涉及服务端鉴权。

## 3. 页面设计

### 3.1 登录页

元素：

- StreamForge 标题。
- 账号输入框。
- 密码输入框。
- 登录按钮。
- 注册入口。

行为：

- 点击登录后调用 Java 用户服务登录接口。
- 登录成功后保存 `userId`、`account`、`username`。
- 登录失败时使用 Element Plus 消息提示错误。

### 3.2 注册页

元素：

- 账号输入框。
- 密码输入框。
- 用户名输入框。
- 注册按钮。
- 返回登录入口。

行为：

- 前端做必填和长度校验。
- 注册成功后保存用户信息并进入首页，或跳转登录页。
- 账号重复时展示服务端错误。

### 3.3 首页

元素：

- 当前用户信息。
- 创建房间按钮。
- 房间号输入框。
- 加入房间按钮。
- 退出登录按钮。

行为：

- 创建房间调用 Go 房间服务 REST 接口，成功后保存 LiveKit 连接信息并跳转 `/rooms/:roomId`。
- 加入房间调用 Go 房间服务 REST 接口，成功后保存 LiveKit 连接信息并跳转 `/rooms/:roomId`。
- 退出登录清理本地用户状态并跳转登录页。

### 3.4 房间页

布局：

```text
┌────────────────────────────────────────────┐
│ 顶部栏：房间号、LiveKit 连接状态、当前用户   │
├───────────────────────────────┬────────────┤
│                               │ 成员列表    │
│ 视频宫格 / 屏幕共享主画面      ├────────────┤
│                               │ 聊天面板    │
├───────────────────────────────┴────────────┤
│ 底部媒体控制栏                              │
└────────────────────────────────────────────┘
```

移动端：

- 视频区域优先。
- 聊天和成员列表可以用抽屉或标签切换。
- 底部控制栏固定在底部。

视频展示规则：

- 视频宫格以 LiveKit `participant identity` 为单位渲染，一个参与者只对应一个普通视频卡片，不按 Track 数量生成卡片。
- 摄像头 Track、麦克风 Track 和屏幕共享 Track 聚合到同一个参与者视图；麦克风 Track 仅通过隐藏音频元素播放，不显示独立语音窗口。
- 摄像头关闭、静音、Track 重新发布或重连时保留参与者卡片和原有顺序；没有摄像头画面时显示姓名头像占位。
- 普通宫格中本地用户固定在第一位，远端用户按首次加入顺序排列，新加入用户追加到末尾。
- 桌面端按人数使用固定列数：1 人单列、2 人两列、3-4 人两列、5-6 人三列、7-8 人四列；可用宽度不足时降列，移动端使用单列。
- 屏幕共享使用独立主舞台，普通参与者显示在缩略区；多个共享同时存在时展示最近开始的共享，停止后恢复原宫格顺序。

## 5. Pinia Store

### 5.1 `authStore`

状态：

```ts
interface AuthState {
  userId: number | null
  account: string
  username: string
}
```

职责：

- 保存登录用户信息。
- 从 localStorage 恢复用户信息。
- 登录成功后写入用户信息。
- 退出登录时清理用户信息。

### 5.2 `roomStore`

状态：

```ts
interface RoomState {
  roomId: string
  livekitRoomName: string
  livekitUrl: string
  livekitToken: string
  appWsUrl: string
  joined: boolean
}
```

职责：

- 保存当前业务房间 ID。
- 保存 LiveKit 房间名和连接凭证。
- 保存可选 Go WebSocket 聊天地址。
- 进入房间和离开房间时清理状态。

### 5.3 `livekitStore`

状态：

```ts
interface LiveKitState {
  status: 'idle' | 'connecting' | 'connected' | 'reconnecting' | 'failed' | 'closed'
  participants: ParticipantView[]
  localParticipantId: string
  activeScreenShareParticipantId: string
  errorMessage: string
}
```

职责：

- 管理 LiveKit 连接状态。
- 维护参与者列表和媒体状态。
- 保存本地和远端 Track 的 UI 映射。
- 处理屏幕共享展示。

### 5.4 `mediaStore`

状态：

```ts
interface MediaState {
  audioEnabled: boolean
  videoEnabled: boolean
  screenSharing: boolean
  selectedAudioInputId: string
  selectedVideoInputId: string
}
```

职责：

- 调用 LiveKit SDK 控制麦克风、摄像头和屏幕共享。
- 切换麦克风和摄像头。
- 根据 LiveKit 事件更新远端 Peer 的媒体状态。

### 5.5 `chatStore`

状态：

```ts
interface ChatState {
  messages: ChatMessage[]
  unreadCount: number
}
```

职责：

- 保存当前房间内的临时聊天消息。
- 发送聊天消息。
- 接收 `chat.message` 或后续 LiveKit data packet。
- MVP 不做本地持久化。

### 5.6 `connectionStore`

状态：

```ts
type AppWsStatus = 'idle' | 'connecting' | 'connected' | 'closed' | 'error'
type LiveKitStatus = 'idle' | 'connecting' | 'connected' | 'reconnecting' | 'failed' | 'closed'
```

职责：

- 展示 Go WebSocket 和 LiveKit 连接状态。
- 管理连接错误提示。
- 辅助房间页按钮禁用和重试。

## 6. API 模块

建议目录：

```text
src/api/user.ts
src/api/room.ts
src/signaling/client.ts
src/livekit/client.ts
```

### 6.1 用户 API

- `register(account, password, username)`
- `login(account, password)`
- `getUser(userId)`

### 6.2 房间 API

- `createRoom(userId, username)`，返回 `roomId/livekitRoomName/livekitUrl/livekitToken/appWsUrl`
- `joinRoom(roomId, userId, username)`，返回同上

### 6.3 WebSocket 客户端

职责：

- 建立 Go WebSocket 聊天连接。
- 发送统一消息 envelope。
- 根据 `type` 分发服务端消息。
- 维护 ping / pong。
- 关闭连接。

### 6.4 LiveKit 客户端

职责：

- 创建和维护 LiveKit `Room` 实例。
- 连接 `livekitUrl + livekitToken`。
- 启用/关闭摄像头和麦克风。
- 开启/停止屏幕共享。
- 监听远端 Track、参与者、重连和错误事件。
- 按参与者身份聚合本地和远端摄像头、麦克风及屏幕共享 Track，再暴露给组件渲染。
- 只把远端麦克风 Track 交给隐藏音频渲染层，本地麦克风不回放以避免回声。

## 7. 房间页状态流

```text
进入 /rooms/:roomId
  -> 检查 authStore
  -> 调用 joinRoom REST
  -> 保存 livekitUrl/livekitToken/appWsUrl
  -> 创建 LiveKit Room
  -> room.connect(livekitUrl, livekitToken)
  -> 开启摄像头和麦克风
  -> 监听 TrackSubscribed 渲染远端音视频
  -> 可选建立 Go WebSocket 用于聊天
```

## 8. UI 规范

- 使用 Element Plus 表单、按钮、弹窗、消息提示、抽屉、标签页。
- 会议主界面应以功能可用和信息清晰为优先，不做营销式首页。
- 视频宫格需要稳定尺寸，避免参与者加入离开时 UI 大幅跳动。
- 普通参与者卡片统一使用 16:9；摄像头画面使用 `object-fit: cover`，屏幕共享主画面使用 `object-fit: contain`。
- 底部控制栏使用图标按钮配合 tooltip。
- 聊天输入框支持回车发送，Shift + Enter 换行可以作为 P1。
- 错误提示使用 `ElMessage` 或 `ElAlert`。
- 连接中、无摄像头、摄像头关闭时需要有明确占位状态。

## 9. 错误状态

| 场景 | 前端行为 |
|:---|:---|
| 登录失败 | 展示错误消息，不跳转 |
| 注册账号重复 | 展示账号已存在 |
| 房间不存在 | 返回首页或留在输入页并提示 |
| LiveKit Token 获取失败 | 提示加入失败，允许重试 |
| 媒体权限被拒绝 | 提示权限问题，允许留在房间聊天 |
| Go WebSocket 断开 | 显示聊天断开状态，音视频不应立即中断 |
| LiveKit 连接失败 | 显示连接失败，提供重新加入按钮 |
| 屏幕共享取消 | UI 恢复未共享状态 |

## 10. 验收点

- 用户可以完成注册和登录。
- 首页可以创建房间和加入房间。
- 房间页可以显示房间号、用户信息和 LiveKit 连接状态。
- 两个浏览器标签页可以互相看到远端视频。
- 聊天消息能在同房间广播。
- 静音、摄像头关闭、屏幕共享状态能同步到其他参与者。
- 桌面端布局不遮挡主要视频区域。
- 移动端能进入房间并使用基本控制。
