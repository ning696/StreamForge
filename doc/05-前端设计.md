# StreamForge 前端设计

## 1. 目标

前端负责提供可用的视频会议体验，覆盖注册、登录、创建房间、加入房间、音视频通话、屏幕共享、聊天、成员状态和媒体控制。

技术栈固定为：

- Vue 3
- TypeScript
- Vite
- Pinia
- Vue Router
- Element Plus
- 浏览器原生 WebRTC API

## 2. 页面路由

| 路由 | 页面 | 说明 |
|:---|:---|:---|
| `/login` | 登录页 | 输入账号和密码，登录成功后进入首页 |
| `/register` | 注册页 | 输入账号、密码、用户名，注册成功后进入首页或登录页 |
| `/` | 首页 | 展示当前用户、创建房间、输入房间号加入 |
| `/rooms/:roomId` | 房间页 | 视频会议主界面 |
| `/:pathMatch(.*)*` | 404 页 | 未匹配路由 |

未登录用户访问首页和房间页时，跳转到 `/login`。MVP 这里的“未登录”只指前端本地没有用户信息，不涉及服务端鉴权。

## 3. 页面设计

### 3.1 登录页

元素：

- StreamForge 标题。
- 账号输入框。
- 密码输入框。
- 登录按钮。
- 注册入口。

行为：

- 点击登录后调用 Java 用户服务登录接口。
- 登录成功后保存 `userId`、`account`、`username`。
- 登录失败时使用 Element Plus 消息提示错误。

### 3.2 注册页

元素：

- 账号输入框。
- 密码输入框。
- 用户名输入框。
- 注册按钮。
- 返回登录入口。

行为：

- 前端做必填和长度校验。
- 注册成功后保存用户信息并进入首页，或跳转登录页。
- 账号重复时展示服务端错误。

### 3.3 首页

元素：

- 当前用户信息。
- 创建房间按钮。
- 房间号输入框。
- 加入房间按钮。
- 退出登录按钮。

行为：

- 创建房间调用媒体服务 REST 接口，成功后跳转 `/rooms/:roomId`。
- 加入房间调用媒体服务 REST 接口，成功后跳转 `/rooms/:roomId`。
- 退出登录清理本地用户状态并跳转登录页。

### 3.4 房间页

布局：

```text
┌────────────────────────────────────────────┐
│ 顶部栏：房间号、连接状态、当前用户          │
├───────────────────────────────┬────────────┤
│                               │ 成员列表    │
│ 视频宫格 / 屏幕共享主画面      ├────────────┤
│                               │ 聊天面板    │
├───────────────────────────────┴────────────┤
│ 底部媒体控制栏                              │
└────────────────────────────────────────────┘
```

移动端：

- 视频区域优先。
- 聊天和成员列表可以用抽屉或标签切换。
- 底部控制栏固定在底部。

## 5. Pinia Store

### 5.1 `authStore`

状态：

```ts
interface AuthState {
  userId: number | null
  account: string
  username: string
}
```

职责：

- 保存登录用户信息。
- 从 localStorage 恢复用户信息。
- 登录成功后写入用户信息。
- 退出登录时清理用户信息。

### 5.2 `roomStore`

状态：

```ts
interface RoomState {
  roomId: string
  mediaInstanceId: string
  joined: boolean
  peers: PeerState[]
}
```

职责：

- 保存当前房间 ID。
- 保存媒体实例 ID。
- 保存成员列表。
- 处理 `room.snapshot`、`peer.joined`、`peer.left`。

### 5.3 `mediaStore`

状态：

```ts
interface MediaState {
  audioEnabled: boolean
  videoEnabled: boolean
  screenSharing: boolean
  selectedAudioInputId: string
  selectedVideoInputId: string
}
```

职责：

- 管理本地媒体状态。
- 切换麦克风和摄像头。
- 管理屏幕共享状态。
- 根据服务端广播更新远端 Peer 的媒体状态。

### 5.4 `chatStore`

状态：

```ts
interface ChatState {
  messages: ChatMessage[]
  unreadCount: number
}
```

职责：

- 保存当前房间内的临时聊天消息。
- 发送聊天消息。
- 接收 `chat.message`。
- MVP 不做本地持久化。

### 5.5 `connectionStore`

状态：

```ts
interface ConnectionState {
  signalingStatus: 'idle' | 'connecting' | 'connected' | 'closed' | 'error'
  rtcStatus: 'idle' | 'connecting' | 'connected' | 'failed' | 'closed'
  errorMessage: string
}
```

职责：

- 展示连接状态。
- 管理连接错误提示。
- 辅助房间页按钮禁用和重试。

## 6. API 模块

建议目录：

```text
src/api/user.ts
src/api/room.ts
src/signaling/client.ts
src/webrtc/client.ts
```

### 6.1 用户 API

- `register(account, password, username)`
- `login(account, password)`
- `getUser(userId)`

### 6.2 房间 API

- `createRoom(userId, username)`
- `joinRoom(roomId, userId, username)`

### 6.3 WebSocket 客户端

职责：

- 建立连接。
- 发送统一消息 envelope。
- 根据 `type` 分发服务端消息。
- 维护 ping / pong。
- 关闭连接。

### 6.4 WebRTC 客户端

职责：

- 获取本地媒体。
- 创建 RTCPeerConnection。
- 添加和替换 Track。
- 创建 Offer。
- 应用 Answer。
- 处理 ICE Candidate。
- 暴露远端 MediaStream 给组件。

## 7. 房间页状态流

```text
进入 /rooms/:roomId
  -> 检查 authStore
  -> 调用 joinRoom REST
  -> 保存 mediaInstanceId 和 wsUrl
  -> 建立 WebSocket
  -> 发送 room.join
  -> 获取本地媒体
  -> 创建 RTCPeerConnection
  -> 发送 webrtc.offer
  -> 收到 webrtc.answer
  -> 交换 ICE Candidate
  -> 渲染本地和远端视频
```

## 8. UI 规范

- 使用 Element Plus 表单、按钮、弹窗、消息提示、抽屉、标签页。
- 会议主界面应以功能可用和信息清晰为优先，不做营销式首页。
- 视频宫格需要稳定尺寸，避免参与者加入离开时 UI 大幅跳动。
- 底部控制栏使用图标按钮配合 tooltip。
- 聊天输入框支持回车发送，Shift + Enter 换行可以作为 P1。
- 错误提示使用 `ElMessage` 或 `ElAlert`。
- 连接中、无摄像头、摄像头关闭时需要有明确占位状态。

## 9. 错误状态

| 场景 | 前端行为 |
|:---|:---|
| 登录失败 | 展示错误消息，不跳转 |
| 注册账号重复 | 展示账号已存在 |
| 房间不存在 | 返回首页或留在输入页并提示 |
| 媒体权限被拒绝 | 提示权限问题，允许留在房间聊天 |
| WebSocket 断开 | 显示断开状态，允许用户离开并重新加入 |
| WebRTC 连接失败 | 显示连接失败，提供重新加入按钮 |
| 屏幕共享取消 | UI 恢复未共享状态 |

## 10. 验收点

- 用户可以完成注册和登录。
- 首页可以创建房间和加入房间。
- 房间页可以显示房间号、用户信息和连接状态。
- 两个浏览器标签页可以互相看到远端视频。
- 聊天消息能在同房间广播。
- 静音、摄像头关闭、屏幕共享状态能同步到其他参与者。
- 桌面端布局不遮挡主要视频区域。
- 移动端能进入房间并使用基本控制。
