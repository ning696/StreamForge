# StreamForge 数据与状态模型

## 1. 数据分类

StreamForge MVP 中的数据分为三类：

| 类型 | 存储位置 | 示例 |
|:---|:---|:---|
| 持久化业务数据 | MySQL | 用户账号、密码哈希、用户名 |
| 运行时协调数据 | Redis | 媒体实例心跳、房间路由、在线状态摘要 |
| 进程内实时对象 | Go 媒体实例内存 | WebSocket 连接、PeerConnection、Track、Room、Peer |

设计原则：

- MySQL 保存需要长期存在的数据。
- Redis 保存可重建、可过期、可序列化的运行时协调数据。
- WebRTC 对象和媒体流只存在 Go 进程内存中。

## 2. ID 规则

| ID | 示例 | 生成方 | 说明 |
|:---|:---|:---|:---|
| `userId` | `1` | MySQL | 用户自增主键 |
| `roomId` | `839204` | Go 媒体服务 | 房间号，MVP 可使用 6-8 位数字或短字符串 |
| `peerId` | `peer-7f3a` | Go 媒体实例 | 用户每次加入房间产生的新连接 ID |
| `mediaInstanceId` | `media-001` | Go 媒体实例 | 媒体实例 ID，K8s 中可来自 Pod 名称 |
| `messageId` | `msg-01hxyz` | Go 媒体实例 | 聊天消息 ID |
| `trackId` | `track-01hxyz` | 浏览器或媒体服务 | 媒体轨道 ID |

## 3. MySQL 数据模型

### 3.1 用户表

表名：`users`

```sql
CREATE TABLE users (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  account VARCHAR(32) NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  username VARCHAR(32) NOT NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_users_account (account)
);
```

字段说明：

| 字段 | 说明 |
|:---|:---|
| `id` | 用户 ID |
| `account` | 登录账号，唯一 |
| `password_hash` | 密码哈希，不能存储明文密码 |
| `username` | 用户名，用于会议中展示 |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

### 3.2 用户服务 DTO

注册请求：

```json
{
  "account": "demo",
  "password": "123456",
  "username": "演示用户"
}
```

登录请求：

```json
{
  "account": "demo",
  "password": "123456"
}
```

用户响应：

```json
{
  "userId": 1,
  "account": "demo",
  "username": "演示用户"
}
```

## 4. Redis 数据模型

Redis key 统一使用 `streamforge:` 前缀。

### 4.1 媒体实例集合

```text
streamforge:media:instances
```

类型：Set

成员：

```text
media-001
media-002
media-003
```

用途：

- 查询当前已注册媒体实例。
- 创建房间时选择候选实例。

### 4.2 媒体实例详情

```text
streamforge:media:instance:{mediaInstanceId}
```

类型：Hash

示例：

```text
id = media-001
host = media-service-001.streamforge.svc.cluster.local
httpPort = 8080
wsPort = 8080
rtcPortRange = 30000-30100
status = healthy
startedAt = 1783072800000
lastHeartbeatAt = 1783072860000
roomCount = 3
peerCount = 12
```

TTL：心跳周期的 3 倍。例如心跳 10 秒，TTL 30 秒。

### 4.3 房间路由

```text
streamforge:room:{roomId}:instance
```

类型：String

示例：

```text
media-001
```

用途：

- 保存 `roomId -> mediaInstanceId`。
- 加入房间时必须读取该 key。

TTL：

- 房间有成员时持续刷新。
- 房间为空后可以立即删除或设置短 TTL。

### 4.4 房间状态摘要

```text
streamforge:room:{roomId}:meta
```

类型：Hash

示例：

```text
roomId = 839204
mediaInstanceId = media-001
createdByUserId = 1
createdAt = 1783072800000
peerCount = 4
status = active
```

用途：

- 便于调试和简单状态展示。
- 不作为真实房间成员状态的唯一来源。

### 4.5 房间在线成员摘要

```text
streamforge:room:{roomId}:peers
```

类型：Hash

字段：

```text
peer-abc = {"userId":1,"username":"演示用户","joinedAt":1783072800000}
```

用途：

- 临时在线状态摘要。
- 实例异常排查。

注意：真实 Peer 对象仍以 Go 内存为准。

## 5. Go 内存模型

### 5.1 MediaInstance

```text
MediaInstance
  id
  startedAt
  rooms
  redisClient
  heartbeatLoop
```

职责：

- 注册实例。
- 周期心跳。
- 管理本实例内的房间。
- 上报房间数和 Peer 数。

### 5.2 Room

```text
Room
  roomId
  mediaInstanceId
  createdByUserId
  peers
  trackPublications
  createdAt
```

职责：

- 管理同一房间内 Peer。
- 广播成员加入离开。
- 广播聊天消息。
- 管理 Track 发布关系。

### 5.3 Peer

```text
Peer
  peerId
  userId
  username
  websocket
  peerConnection
  mediaState
  joinedAt
```

职责：

- 表示一个用户在某房间内的一次连接。
- 维护 WebSocket。
- 维护 PeerConnection。
- 维护媒体状态。

### 5.4 TrackPublication

```text
TrackPublication
  trackId
  peerId
  kind
  source
  enabled
```

`source` 可选值：

- `audio`
- `camera`
- `screen`

### 5.5 ChatMessage

```text
ChatMessage
  messageId
  roomId
  peerId
  userId
  username
  content
  sentAt
```

MVP 中聊天消息不落 MySQL。

## 6. 前端状态模型

### 6.1 用户状态

```ts
interface UserSession {
  userId: number
  account: string
  username: string
}
```

存储位置：

- Pinia。
- localStorage。

### 6.2 房间状态

```ts
interface PeerState {
  peerId: string
  userId: number
  username: string
  audioEnabled: boolean
  videoEnabled: boolean
  screenSharing: boolean
}

interface CurrentRoom {
  roomId: string
  mediaInstanceId: string
  peers: PeerState[]
}
```

### 6.3 连接状态

```ts
type SignalingStatus = 'idle' | 'connecting' | 'connected' | 'closed' | 'error'
type RtcStatus = 'idle' | 'connecting' | 'connected' | 'failed' | 'closed'
```

## 7. 数据一致性规则

- MySQL 用户账号是持久化事实来源。
- Redis 房间路由是加入房间时的事实来源。
- Go 内存 Room 是房间实时成员和媒体状态的事实来源。
- 前端状态只用于展示和交互，不能作为服务端事实来源。
- 房间为空后，Go 内存房间状态必须释放，Redis 路由必须删除或过期。

## 8. 安全规则

- 数据库不保存明文密码。
- 用户响应不返回 `password_hash`。
- MVP 没有鉴权，不能把该版本暴露为真实生产用户系统。
- 后续引入鉴权时，需要修改前端、用户服务和媒体服务的加入房间流程。

## 9. 验收点

- MySQL 中 `users.account` 有唯一索引。
- 密码字段保存的是哈希，不是明文。
- Redis 中可以看到媒体实例心跳。
- 创建房间后 Redis 中出现 `roomId -> mediaInstanceId`。
- 同一房间多用户加入时 Redis 路由不变化。
- Go 进程退出后，其内存 PeerConnection 和 Track 不依赖 Redis 恢复。
