# StreamForge 数据与状态模型

## 1. 数据分类

StreamForge MVP 中的数据分为四类：

| 类型 | 存储位置 | 示例 |
|:---|:---|:---|
| 持久化业务数据 | MySQL | 用户账号、密码哈希、用户名 |
| StreamForge 运行时摘要 | Redis | 业务房间摘要、临时在线状态、调试状态 |
| LiveKit 运行时协调 | Redis / LiveKit 内部 | LiveKit 节点协调、房间和参与者运行态 |
| 浏览器/LiveKit 媒体对象 | 浏览器和 LiveKit 内存 | PeerConnection、SDP、ICE、Track、RTP/RTCP |

设计原则：

- MySQL 保存需要长期存在的数据。
- StreamForge Redis 只保存可重建、可过期、可序列化的业务运行时摘要。
- LiveKit 负责媒体运行态和集群协调。
- StreamForge 不保存 WebRTC 对象和媒体流。

## 2. ID 规则

| ID | 示例 | 生成方 | 说明 |
|:---|:---|:---|:---|
| `userId` | `1` | MySQL | 用户自增主键 |
| `roomId` | `839204` | Go 房间服务 | StreamForge 展示给用户的业务房间号 |
| `livekitRoomName` | `streamforge-839204` | Go 房间服务 | LiveKit 实际房间名 |
| `livekitIdentity` | `user-1-a1b2c3d4` | Go 房间服务 | LiveKit participant identity，MVP 可由 userId 派生 |
| `appPeerId` | `app-peer-7f3a` | Go 房间服务 | StreamForge WebSocket 聊天连接 ID |
| `messageId` | `msg-01hxyz` | Go 房间服务 | 聊天消息 ID |
| `trackSid` | `TR_xxx` | LiveKit | LiveKit Track 标识 |

## 3. MySQL 数据模型

### 3.1 用户表

表名：`users`

```sql
CREATE TABLE users (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  account VARCHAR(32) NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  username VARCHAR(32) NOT NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_users_account (account)
);
```

字段说明：

| 字段 | 说明 |
|:---|:---|
| `id` | 用户 ID |
| `account` | 登录账号，唯一 |
| `password_hash` | 密码哈希，不能存储明文密码 |
| `username` | 用户名，用于会议中展示 |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

### 3.2 用户服务 DTO

注册请求：

```json
{
  "account": "demo",
  "password": "123456",
  "username": "演示用户"
}
```

登录请求：

## 4. Redis 数据模型

Redis key 统一使用 `streamforge:` 前缀，避免和 LiveKit 自身 Redis key 混淆。生产环境可以给 StreamForge 和 LiveKit 使用不同 Redis database 或不同 Redis 实例。

### 4.1 业务房间摘要

```text
streamforge:room:{roomId}:meta
```

类型：Hash

示例：

```text
roomId = 839204
livekitRoomName = streamforge-839204
createdByUserId = 1
createdAt = 1783072800000
status = active
```

用途：

- 判断业务房间是否存在。
- 加入房间时找到对应 `livekitRoomName`。
- 便于调试和简单状态展示。

TTL：

- MVP 可使用较长 TTL，例如 24 小时。
- 房间为空后可以删除或设置短 TTL。

### 4.2 房间在线成员摘要

```text
streamforge:room:{roomId}:peers
```

类型：Hash

字段：

```text
app-peer-abc = {"userId":1,"username":"演示用户","livekitIdentity":"user-1","joinedAt":1783072800000}
```

用途：

- Go WebSocket 聊天在线状态。
- 调试和临时展示。

注意：真实媒体参与者状态以 LiveKit 为准。

### 4.3 最近聊天消息（可选）

```text
streamforge:room:{roomId}:recent_messages
```

类型：List

用途：

- 可选的短期调试或断线后补齐。
- MVP 不作为聊天记录持久化查询能力。

TTL：短 TTL，例如 1-24 小时。

### 4.4 不再使用的旧媒体路由 key

LiveKit 独立集群方案不再使用以下旧模型作为媒体事实源：

```text
streamforge:media:instances
streamforge:media:instance:{mediaInstanceId}
streamforge:room:{roomId}:instance
```

如旧代码仍存在这些 key，应在迁移阶段逐步删除或仅保留兼容测试，不作为新方案实现依据。

## 5. Go 内存模型

### 5.1 Room

```text
Room
  roomId
  livekitRoomName
  createdByUserId
  createdAt
  status
```

职责：

- 表示 StreamForge 业务房间。
- 维护业务房间摘要。
- 映射到 LiveKit room name。

### 5.2 AppPeer

```text
AppPeer
  appPeerId
  userId
  username
  livekitIdentity
  websocket
  joinedAt
```

职责：

- 表示一个用户在 StreamForge WebSocket 聊天通道中的连接。
- 不表示 LiveKit 媒体连接。
- 不维护 PeerConnection 或 Track。

### 5.3 ChatMessage

```text
ChatMessage
  messageId
  roomId
  appPeerId
  userId
  username
  content
  sentAt
```

MVP 中聊天消息不落 MySQL。

### 5.4 LiveKitTokenClaims

```text
LiveKitTokenClaims
  roomName
  identity
  name
  metadata
  canJoin
  expiresAt
```

职责：

- 表示后端签发 LiveKit Token 时使用的业务输入。
- API secret 只能存在后端配置中。

## 7. 数据一致性规则

- MySQL 用户账号是持久化事实来源。
- StreamForge Redis 业务房间摘要是创建/加入业务房间的辅助事实来源。
- LiveKit 是媒体房间、参与者媒体状态和 Track 的事实来源。
- Go WebSocket 内存状态只表示聊天/业务连接状态。
- 前端状态只用于展示和交互，不能作为服务端事实来源。
- 房间为空后，业务摘要可以删除或过期；LiveKit 媒体房间由 LiveKit 自行释放。

## 8. 安全规则

- 数据库不保存明文密码。
- 用户响应不返回 `password_hash`。
- `LIVEKIT_API_SECRET` 只能存放在后端环境变量或 Secret 中，不能进入前端包。
- LiveKit Token 应设置合理有效期。
- MVP 没有完整鉴权，不能把该版本暴露为真实生产用户系统。
- 后续引入完整鉴权时，需要修改前端、用户服务和房间服务的创建/加入房间流程。

## 9. 验收点

- MySQL 中 `users.account` 有唯一索引。
- 密码字段保存的是哈希，不是明文。
- 创建房间后 Redis 中可以出现业务房间摘要。
- 创建/加入房间后返回有效 `livekitRoomName`、`livekitUrl`、`livekitToken` 和 `livekitIdentity`。
- StreamForge Redis 不保存 WebRTC PeerConnection、Track、SDP 或 ICE Candidate。
- 前端使用 LiveKit participant/track 事件维护媒体 UI。
