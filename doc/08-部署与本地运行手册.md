# StreamForge 部署与本地运行手册

## 1. 部署目标

MVP 需要支持两种运行方式：

- 本地开发：Docker Compose 启动完整依赖，便于联调。
- MVP 部署：Kubernetes Manifest 部署前端、用户服务、Go 房间服务、LiveKit、MySQL、Redis。

LiveKit 独立集群负责 WebRTC/SFU。Go 房间服务负责创建/加入房间和签发 LiveKit Token。

## 2. 服务清单

| 服务 | 默认端口 | 说明 |
|:---|:---:|:---|
| frontend | 5173 / 8088（1Panel 回源） | Vue 前端开发或静态资源服务；生产环境由 1Panel OpenResty 占用 80/443 |
| user-service | 8081 | Java Spring Boot 用户服务 |
| room-service / media-service | 8080 | Go 房间服务 HTTP / WebSocket 入口；当前代码目录仍可能叫 `media-service` |
| livekit | 7880 / 7881 / UDP range | LiveKit 信令和 WebRTC RTC 服务 |
| mysql | 3306 | 用户账号数据库 |
| redis | 6379 | LiveKit 协调和 StreamForge 运行时摘要 |

LiveKit WebRTC 媒体端口需要独立规划，示例端口范围：

```text
30000-30100/UDP
```

## 3. 环境变量

### 3.1 前端

| 变量 | 示例 | 说明 |
|:---|:---|:---|
| `VITE_USER_API_BASE_URL` | 开发：`http://localhost:8081`；部署包：`/` | 用户服务地址；部署包使用同源 Nginx 反向代理 |
| `VITE_MEDIA_API_BASE_URL` | 开发：`http://localhost:8080`；部署包：`/` | Go 房间服务 REST 地址；部署包使用同源 Nginx 反向代理 |
| `VITE_APP_WS_BASE_URL` | `ws://localhost:8080` | Go WebSocket 聊天基础地址，若后端直接返回 `appWsUrl` 可选 |

LiveKit 真实连接地址由创建/加入房间接口返回的 `livekitUrl` 决定，不建议在前端硬编码 API secret。

Windows 发布构建使用 `deploy/StreamForge/build.ps1`。脚本在未显式配置上述两个 API
变量时默认注入 `/`，并在构建后检查静态 JavaScript，防止 `localhost:8081` 或
`localhost:8080` 被误打入服务器部署包。

#### 局域网 HTTPS 开发联调

局域网设备需要摄像头、麦克风时，前端必须运行在浏览器信任的 HTTPS 安全上下文中。
开发环境可以在 `frontend/certs/` 放置 `mkcert` 生成的 `dev-cert.pem` 与
`dev-key.pem`，由 Vite 的 HTTPS 开发服务器统一代理：

- `/api/users` 到本机用户服务 `8081`；
- `/api/rooms` 到本机房间服务 `8080`；
- `/ws/rooms` 到本机房间服务 WebSocket；
- `/livekit` 到本机 LiveKit 信令端口 `7880`。

此模式下前端的两个 API 基础地址均设置为 `/`；房间服务返回的应用 WebSocket 地址为
`wss://<局域网IP>:5173`，LiveKit 信令地址为
`wss://<局域网IP>:5173/livekit`。LiveKit RTC 媒体流不经过 Vite，仍通过
`rtc.node_ip`、`7881/TCP` 和 `30000-30100/UDP` 直连。证书私钥不得提交到仓库；
参与测试的其他设备只安装开发 CA 的 `rootCA.pem`，不得复制 `rootCA-key.pem`。

### 3.2 用户服务

| 变量 | 示例 | 说明 |
|:---|:---|:---|
| `SERVER_PORT` | `8081` | 用户服务端口 |
| `MYSQL_HOST` | `mysql` | MySQL 主机 |
| `MYSQL_PORT` | `3306` | MySQL 端口 |
| `MYSQL_DATABASE` | `streamforge` | 数据库名 |
| `MYSQL_USERNAME` | `streamforge` | 数据库用户 |
| `MYSQL_PASSWORD` | `streamforge_password` | 数据库密码 |

本地直接用 IDEA 或命令行启动 `user-service` 时，可以在 `user-service/.env` 放置上述环境变量。

### 3.3 Go 房间服务

| 变量 | 示例 | 说明 |
|:---|:---|:---|
| `SERVER_PORT` | `8080` | HTTP / WebSocket 端口 |
| `PUBLIC_HTTP_BASE_URL` | `http://localhost:8080` | 返回给前端的 HTTP 基础地址 |
| `PUBLIC_WS_BASE_URL` | `ws://localhost:8080` | 返回给前端的 WebSocket 基础地址 |
| `REDIS_HOST` | `redis` | Redis 主机 |
| `REDIS_PORT` | `6379` | Redis 端口 |
| `REDIS_PASSWORD` | 空 | Redis 密码，本地无密码时留空 |
| `REDIS_DB` | `0` | Redis 数据库编号 |
| `LIVEKIT_URL` | `ws://localhost:7880` | 返回给前端的 LiveKit 信令地址 |
| `LIVEKIT_API_KEY` | `devkey` | LiveKit API key |
| `LIVEKIT_API_SECRET` | `secret` | LiveKit API secret，只能在后端保存 |
| `LIVEKIT_TOKEN_TTL_SECONDS` | `86400` | LiveKit Token 有效期 |

本地直接用 GoLand 或命令行启动 Go 房间服务时，可以在服务目录 `.env` 放置上述环境变量。

### 3.4 LiveKit

| 变量 / 配置 | 示例 | 说明 |
|:---|:---|:---|
| `LIVEKIT_KEYS` | `devkey: secret` | 本地开发 key/secret |
| `port` | `7880` | LiveKit 信令端口 |
| `rtc.tcp_port` | `7881` | LiveKit TCP fallback 端口 |
| `rtc.port_range_start` | `30000` | RTC UDP 端口起始 |
| `rtc.port_range_end` | `30100` | RTC UDP 端口结束 |
| `redis.address` | `redis:6379` | LiveKit 多节点协调 Redis |
| `rtc.use_external_ip` / `rtc.node_ip` | `false` / `127.0.0.1` | 本地 Docker 使用 `node_ip` 通告宿主机可达地址；云环境通常需要 `use_external_ip` 或显式公网 IP |

生产环境不要使用开发默认 key/secret。

本地 Docker Compose 使用 `deploy/livekit/livekit.yaml` 显式固定 LiveKit RTC 配置，确保 LiveKit 实际使用的 UDP 端口范围与 Docker 暴露的 `30000-30100/udp` 一致。仅访问 `http://localhost:7880` 正常只能证明信令入口可达，不能证明 WebRTC ICE/RTC 媒体端口可达。

### 3.5 MySQL

| 变量 | 示例 | 说明 |
|:---|:---|:---|
| `MYSQL_ROOT_PASSWORD` | `root_password` | root 密码 |
| `MYSQL_DATABASE` | `streamforge` | 默认数据库 |
| `MYSQL_USER` | `streamforge` | 应用用户 |
| `MYSQL_PASSWORD` | `streamforge_password` | 应用用户密码 |

## 4. 本地 Docker Compose 目标

docker-compose 应包含：

```text
services:
  frontend
  user-service
  room-service 或 media-service
  livekit
  mysql
  redis
```

本地启动目标命令：

```bash
docker compose up --build
```

本地验收：

- 前端可以打开。
- 用户可以注册和登录。
- 创建房间后返回 `livekitUrl` 和 `livekitToken`。
- 两个浏览器标签页可以加入同一房间聊天。
- 浏览器允许摄像头和麦克风后可以通过 LiveKit 通话。

## 5. 本地 LiveKit 验证

验证点：

- LiveKit 服务启动成功。
- Go 房间服务使用相同 API key/secret 签发 Token。
- 前端使用 Token 可连接 LiveKit。
- 同一业务 `roomId` 映射到同一 `livekitRoomName`。
- 2 个和 4 个浏览器标签页可以完成音视频通话。

注意：本地测试通常可以使用 `localhost` 和 HTTP。非 localhost 环境需要 HTTPS，并正确开放 LiveKit RTC 端口。

### 6.1 Frontend

资源：

- Deployment

### 6.2 User Service

资源：

- Deployment
- Service

- Secret

依赖：

- MySQL

### 6.3 Go Room Service

资源：

- Deployment
- Service
- ConfigMap
- Secret

要求：

- 可以横向扩展为多个副本。
- 所有副本使用同一 `LIVEKIT_URL`、`LIVEKIT_API_KEY`、`LIVEKIT_API_SECRET`。
- 不需要媒体实例 ID。
- 不暴露 RTC UDP 端口。

### 6.4 LiveKit

资源：

- Deployment 或 StatefulSet。
- Service。
- ConfigMap。
- Secret。

要求：

- 暴露 LiveKit 信令端口。
- 暴露 RTC UDP 端口范围。
- 配置 Redis 地址。
- 云环境需要配置公网 IP、LoadBalancer、NodePort、HostNetwork 或 TURN。
- 生产环境建议启用 TLS 和 TURN/TLS。

### 6.5 MySQL

MVP 可使用：

- Deployment + PersistentVolumeClaim。
- 或 StatefulSet + PersistentVolumeClaim。
- 或外部托管 MySQL。

开发和演示环境可以使用单实例 MySQL。生产环境应使用高可用数据库。

### 6.6 Redis

MVP 可使用单实例 Redis。生产环境应使用高可用 Redis。

Redis 故障会影响：

- LiveKit 多节点协调。
- StreamForge 业务房间摘要。
- Go 房间服务的可过期在线状态。

## 7. Ingress 与 WebRTC 注意事项

HTTP REST、Go WebSocket 聊天和 LiveKit 信令可以通过 Nginx Ingress 或负载均衡暴露。

LiveKit 媒体流通常使用 UDP，不能只依赖普通 HTTP Ingress。部署时需要规划：

- UDP NodePort。
- LoadBalancer UDP 端口。
- HostNetwork。
- TURN 服务。
- LiveKit `use_external_ip` 或显式公网 IP 配置。

MVP 文档和配置需要明确当前采用哪种端口暴露方式。开发环境可以先使用 `localhost` 和局域网验证。

## 8. HTTPS 要求

浏览器调用摄像头、麦克风、屏幕共享通常要求安全上下文：

- `localhost` 可在 HTTP 下使用。
- 非 localhost 环境需要 HTTPS。

K8s Ingress 部署应准备 TLS 配置。MVP 可以先提供自签名或开发证书说明，但真实浏览器访问建议使用受信任证书。

### 8.1 1Panel / OpenResty HTTPS 部署

服务器使用 1Panel 时，推荐让 OpenResty 独占公网 `80/443`：

- `meet.beichuang.art` 反向代理到 StreamForge 前端回源端口 `8088`；
- `livekit.beichuang.art` 反向代理到 LiveKit 信令端口 `7880`，并启用 WebSocket Upgrade；
- 房间服务使用 `PUBLIC_WS_BASE_URL=wss://meet.beichuang.art`；
- 房间服务使用 `LIVEKIT_URL=wss://livekit.beichuang.art`；
- `8088` 和 `7880` 仅作为回源端口，不在云安全组中向公网开放；
- LiveKit 的 `7881/TCP` 与配置的 RTC UDP 端口范围仍需直接开放。

此调整会改变部署入口，但不改变 REST、WebSocket 消息或房间数据结构。旧的
`http://公网IP` / `ws://公网IP` 入口不再作为生产入口，部署更新后客户端必须使用
HTTPS/WSS 域名重新连接。

## 12. 常见问题

### 12.1 摄像头无法打开

检查：

- 浏览器权限。
- 是否 HTTPS 或 localhost。
- 是否有其他应用占用摄像头。

### 12.2 Go WebSocket 连接失败

检查：

- Ingress 是否支持 WebSocket Upgrade。
- 前端 `VITE_APP_WS_BASE_URL` 或后端返回的 `appWsUrl` 是否正确。
- Go 房间服务是否健康。

### 12.3 LiveKit 连接失败

检查：

- `LIVEKIT_URL` 是否是前端可访问地址。
- Go 房间服务和 LiveKit 是否使用同一 API key/secret。
- Token 是否过期。
- LiveKit 信令端口是否开放。
- 浏览器控制台 LiveKit 错误。

### 12.4 音视频无法连通

检查：

- LiveKit RTC UDP 端口是否开放。
- 本地 Compose 的 `deploy/livekit/livekit.yaml` 中 `rtc.port_range_start` / `rtc.port_range_end` 是否与 Docker 暴露端口一致。
- 如果 `http://localhost:7880` 正常但浏览器报 `could not establish pc connection`，优先检查 ICE/RTC UDP 端口和 LiveKit 通告地址，而不是只看容器是否 `Up`。
- LiveKit 是否正确配置公网 IP、`rtc.node_ip` 或 `use_external_ip`。
- STUN / TURN 配置是否正确。
- 企业网络是否阻断 UDP，必要时配置 TURN/TLS。

### 12.5 同一业务房间进入了不同 LiveKit 房间

检查：

- Go 房间服务的 `roomId -> livekitRoomName` 映射是否稳定。
- 创建和加入房间是否使用同一 `roomId`。
- 前端是否复用了正确的 REST 响应。
