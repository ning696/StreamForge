# StreamForge 部署与本地运行手册

## 1. 部署目标

MVP 需要支持两种运行方式：

- 本地开发：Docker Compose 启动完整依赖，便于联调。
- MVP 部署：Kubernetes Manifest 部署前端、用户服务、媒体服务、MySQL、Redis。

媒体服务在 Kubernetes 中必须支持多副本部署，并通过 Redis 房间级路由保证同一房间固定到同一媒体实例。

## 2. 服务清单

| 服务 | 默认端口 | 说明 |
|:---|:---:|:---|
| frontend | 5173 / 80 | Vue 前端开发或静态资源服务 |
| user-service | 8081 | Java Spring Boot 用户服务 |
| media-service | 8080 | Go 媒体服务 HTTP / WebSocket 入口 |
| mysql | 3306 | 用户账号数据库 |
| redis | 6379 | 媒体实例心跳和房间路由 |

WebRTC 媒体端口需要独立规划，示例端口范围：

```text
30000-30100/UDP
```

## 3. 环境变量

### 3.1 前端

| 变量 | 示例 | 说明 |
|:---|:---|:---|
| `VITE_USER_API_BASE_URL` | `http://localhost:8081` | 用户服务地址 |
| `VITE_MEDIA_API_BASE_URL` | `http://localhost:8080` | 媒体服务 REST 地址 |
| `VITE_MEDIA_WS_BASE_URL` | `ws://localhost:8080` | 媒体服务 WebSocket 地址 |

### 3.2 用户服务

| 变量 | 示例 | 说明 |
|:---|:---|:---|
| `SERVER_PORT` | `8081` | 用户服务端口 |
| `MYSQL_HOST` | `mysql` | MySQL 主机 |
| `MYSQL_PORT` | `3306` | MySQL 端口 |
| `MYSQL_DATABASE` | `streamforge` | 数据库名 |
| `MYSQL_USERNAME` | `streamforge` | 数据库用户 |
| `MYSQL_PASSWORD` | `streamforge_password` | 数据库密码 |

### 3.3 媒体服务

| 变量 | 示例 | 说明 |
|:---|:---|:---|
| `MEDIA_INSTANCE_ID` | `media-001` | 媒体实例 ID；K8s 可使用 Pod 名称 |
| `SERVER_PORT` | `8080` | HTTP / WebSocket 端口 |
| `PUBLIC_HTTP_HOST` | `localhost` | 返回给前端的 HTTP 主机 |
| `PUBLIC_WS_HOST` | `localhost` | 返回给前端的 WebSocket 主机 |
| `REDIS_HOST` | `redis` | Redis 主机 |
| `REDIS_PORT` | `6379` | Redis 端口 |
| `RTC_UDP_PORT_MIN` | `30000` | WebRTC UDP 端口起始 |
| `RTC_UDP_PORT_MAX` | `30100` | WebRTC UDP 端口结束 |
| `ICE_STUN_URLS` | `stun:stun.l.google.com:19302` | STUN 配置 |

### 3.4 MySQL

| 变量 | 示例 | 说明 |
|:---|:---|:---|
| `MYSQL_ROOT_PASSWORD` | `root_password` | root 密码 |
| `MYSQL_DATABASE` | `streamforge` | 默认数据库 |
| `MYSQL_USER` | `streamforge` | 应用用户 |
| `MYSQL_PASSWORD` | `streamforge_password` | 应用用户密码 |

## 4. 本地 Docker Compose 目标

docker-compose 应包含：

```text
services:
  frontend
  user-service
  media-service
  mysql
  redis
```

本地启动目标命令：

```bash
docker compose up --build
```

本地验收：

- 前端可以打开。
- 用户可以注册和登录。
- 创建房间后 Redis 出现房间路由。
- 两个浏览器标签页可以加入同一房间聊天。
- 浏览器允许摄像头和麦克风后可以通话。

## 5. 本地多媒体实例验证

本地可以通过扩展媒体服务实例验证房间级路由。

目标命令：

```bash
docker compose up --build --scale media-service=2
```

验证点：

- Redis 中存在两个媒体实例心跳。
- 创建多个房间时可以分配到不同实例。
- 同一房间内所有用户的 `mediaInstanceId` 相同。

注意：本地多实例 WebRTC 端口映射可能需要为每个实例分配不同 UDP 端口范围。开发早期可以先在 K8s 中验证多实例，或为 compose 中的不同实例使用不同端口。

## 6. Kubernetes 部署目标

K8s Manifest 建议目录：

```text
deploy/k8s/
  namespace.yaml
  configmap.yaml
  secret.yaml
  mysql.yaml
  redis.yaml
  user-service.yaml
  media-service.yaml
  frontend.yaml
  ingress.yaml
```

### 6.1 Frontend

资源：

- Deployment
- Service
- Ingress 路由

### 6.2 User Service

资源：

- Deployment
- Service
- ConfigMap
- Secret

依赖：

- MySQL

### 6.3 Media Service

资源：

- Deployment
- Service
- ConfigMap

要求：

- `replicas >= 2` 用于验证 MVP 多实例。
- 每个 Pod 必须拥有唯一 `MEDIA_INSTANCE_ID`。
- Pod 启动后向 Redis 注册心跳。

K8s 中可使用 Pod 名称作为实例 ID：

```yaml
env:
  - name: MEDIA_INSTANCE_ID
    valueFrom:
      fieldRef:
        fieldPath: metadata.name
```

### 6.4 MySQL

MVP 可使用：

- Deployment + PersistentVolumeClaim。
- 或 StatefulSet + PersistentVolumeClaim。
- 或外部托管 MySQL。

开发和演示环境可以使用单实例 MySQL。生产环境应使用高可用数据库。

### 6.5 Redis

MVP 可使用单实例 Redis。生产环境应使用高可用 Redis。

Redis 故障会影响：

- 创建房间。
- 加入房间。
- 媒体实例路由。

## 7. Ingress 与 WebRTC 注意事项

HTTP REST 和 WebSocket 可以通过 Nginx Ingress 暴露。

WebRTC 媒体流通常使用 UDP，不能只依赖普通 HTTP Ingress。部署时需要规划：

- UDP NodePort。
- LoadBalancer UDP 端口。
- HostNetwork。
- TURN 服务。

MVP 文档和配置需要明确当前采用哪种端口暴露方式。开发环境可以先使用 `localhost` 和局域网验证。

## 8. HTTPS 要求

浏览器调用摄像头、麦克风、屏幕共享通常要求安全上下文：

- `localhost` 可在 HTTP 下使用。
- 非 localhost 环境需要 HTTPS。

K8s Ingress 部署应准备 TLS 配置。MVP 可以先提供自签名或开发证书说明。

## 9. 健康检查

### 9.1 用户服务

建议接口：

```text
GET /actuator/health
```

或：

```text
GET /health
```

### 9.2 媒体服务

建议接口：

```text
GET /health
```

响应：

```json
{
  "status": "UP",
  "mediaInstanceId": "media-001",
  "rooms": 3,
  "peers": 12
}
```

### 9.3 Redis 心跳

媒体实例需要定期刷新：

```text
streamforge:media:instance:{mediaInstanceId}
```

K8s readiness 可以只检查本进程健康；业务层实例健康由 Redis 心跳判断。

## 10. 初始数据库

MySQL 初始化需要创建：

- 数据库 `streamforge`。
- 用户表 `users`。
- 应用数据库用户。

用户表 DDL 以 `doc/06-数据与状态模型.md` 为准。

## 11. 部署验收

Docker Compose 验收：

- `frontend` 正常访问。
- `user-service` 健康。
- `media-service` 健康。
- `mysql` 可连接。
- `redis` 可连接。
- 用户可以注册登录。
- 用户可以创建和加入房间。

Kubernetes 验收：

- 所有 Pod Running。
- 前端 Ingress 可访问。
- 用户服务 API 可访问。
- 媒体服务 WebSocket 可连接。
- Redis 中有多个媒体实例心跳。
- 创建房间后 Redis 中有房间路由。
- 同一房间用户固定到同一媒体实例。

## 12. 常见问题

### 12.1 摄像头无法打开

检查：

- 浏览器权限。
- 是否 HTTPS 或 localhost。
- 是否有其他应用占用摄像头。

### 12.2 WebSocket 连接失败

检查：

- Ingress 是否支持 WebSocket Upgrade。
- 前端 `VITE_MEDIA_WS_BASE_URL` 是否正确。
- 媒体服务是否健康。

### 12.3 音视频无法连通

检查：

- ICE Candidate 是否交换。
- UDP 端口是否开放。
- STUN / TURN 配置是否正确。
- 浏览器控制台 WebRTC 连接状态。

### 12.4 同一房间用户被分到不同实例

检查：

- 创建房间是否写入 Redis 路由。
- 加入房间是否读取已有 Redis 路由。
- 是否绕过了媒体路由入口。
- `roomId` 是否一致。
