# ADR 0003：前端 UI 组件库选型

## 状态

Accepted

## 背景

StreamForge 前端需要快速构建登录注册、房间入口、视频会议控制栏、成员列表、聊天面板、弹窗、提示、表单校验和响应式布局。候选方案包括：

- Element Plus。
- Naive UI。
- 自研组件。

## 决策

MVP 阶段固定使用 Element Plus。

## 原因

### Element Plus 适合快速交付

Element Plus 提供成熟的 Vue 3 组件，包括表单、按钮、弹窗、抽屉、消息提示、标签页、布局等。MVP 可以减少基础 UI 开发成本，把精力放在音视频链路和多实例路由上。

### 降低 Codex 实现分歧

如果文档中保留“Element Plus / Naive UI”二选一，后续 Codex 可能混用组件库，造成样式、依赖和交互不一致。固定 Element Plus 可以减少实现分歧。

### 团队维护成本更低

固定单一组件库后，前端依赖、主题、表单校验和弹窗交互更容易统一。

## 影响

正面影响：

- 前端实现速度更快。
- 交互组件一致。
- 文档和代码更容易保持统一。
- 后续 Codex 开发不需要重新选择 UI 组件库。

负面影响：

- 视觉风格会带有 Element Plus 默认特征。
- 深度定制时需要覆盖组件样式。

## 约束

- MVP 不引入 Naive UI。
- MVP 不混用多个 Vue UI 组件库。
- 图标按钮、表单、弹窗、消息提示优先使用 Element Plus 生态。
- 视频宫格和 WebRTC 相关展示组件可以自定义实现。
